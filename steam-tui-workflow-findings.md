# steam-tui CI workflow audit

- Repository: `https://git.valentinus.dev/valeninki/steam-tui.git`, cloned to `/tmp/steam-tui-workflow-audit` at `0f08f632be6ca6d6ab84ec3692f339aac2987223`.
- Changed only `.forgejo/workflows/ci.yaml` in that clone. The workflow now runs `nix flake check` once, instead of first running Rust and Go checks through eight separate `nix develop` invocations and then running `nix flake check` again. The existing checkout and Nix installer stay unchanged.
- Check preservation: `flake.nix` defines one shared `acceptanceCheck` derivation for Cargo formatting, workspace/all-target/all-feature check, three Clippy feature sets, local/headless-CM/all-feature Rust tests, Go vet, Go tests, and CGO-enabled Go race tests. `nix flake check` also builds its `steam-maintain` check. The previous direct commands are covered by this derivation, with extra feature-specific test coverage. This avoids duplicate independent Cargo compilation, and shares one target directory in the acceptance derivation. No unverified Forgejo cache action or extra secret was added.
- Validation: YAML parsed with Python PyYAML `BaseLoader`; `git diff --check` passed; `nix flake check --no-build --show-trace` passed (exit 0), evaluated all five acceptance-check aliases to the same derivation and evaluated `steam-maintain`. Nix emitted only existing metadata warnings about apps lacking `meta` and unknown `homeManagerModules` output.
- Limits: `--no-build` checks evaluation, not actual Rust/Go execution. A full `nix flake check` and remote Forgejo runner job were not run; no performance measurement is claimed. The change is local in the clone, not pushed to Forgejo. The clone has only this workflow modification.
